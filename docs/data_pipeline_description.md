# 1. Introduction

The RetailPulse project is an AI-powered retail analytics system designed to help businesses improve decision-making using historical sales data. The system processes raw retail transaction data, performs data cleaning and feature engineering, and generates insights through visualization and machine learning models.

The data pipeline ensures that raw data is transformed into structured datasets suitable for customer segmentation, demand forecasting, churn prediction, and inventory optimization.

---

# 2. Data Source

Dataset Name:
Online Retail II Dataset

Source:
UCI Machine Learning Repository

File:
online_retail_II.xlsx

The dataset contains two years of retail transaction records with the following attributes:

- Invoice Number
- Stock Code
- Product Description
- Quantity
- Invoice Date
- Unit Price
- Customer ID
- Country

---

# 3. Data Cleaning

The first stage of the pipeline focuses on improving data quality.

Cleaning operations include:

### Removing Duplicate Records

Duplicate transactions are removed to avoid repeated observations during model training.

### Removing Cancelled Orders

Invoices beginning with the character **C** represent cancelled orders.

These transactions are removed because they do not represent actual sales.

### Handling Missing Customer IDs

Rows with missing Customer IDs are removed because customer-based analytics such as segmentation and churn prediction require unique customer identification.

### Removing Invalid Values

Transactions with

- Quantity ≤ 0
- Price ≤ 0

are discarded.

### Date Conversion

InvoiceDate is converted into datetime format for time-based analysis.

### Total Price Calculation

A new feature is created:

```
TotalPrice = Quantity × Price
```

The cleaned dataset is stored as:

```
data/processed/cleaned_data.csv
```

# 4. Feature Engineering

Feature engineering transforms cleaned transactional data into meaningful variables.

### Time Features

The following features are extracted from InvoiceDate:

- Year
- Month
- Quarter
- Week
- Day
- Day of Week
- Hour

These features help identify seasonal demand patterns.

---

### RFM Features

Three important customer behaviour metrics are generated.

#### Recency

Number of days since the customer's last purchase.

#### Frequency

Number of unique invoices generated by the customer.

#### Monetary

Total amount spent by the customer.

These features are later used for customer segmentation and churn prediction.

---

### Customer Features

Additional customer-level metrics include:

- Total Items Purchased
- Average Order Value
- Purchase Count
- Days Since First Purchase
- Purchase Rate

These features help identify valuable and loyal customers.

---

### Time-Series Features

To support forecasting, lag-based features are generated.

Examples:

- Lag1
- Lag7

Rolling statistics include:

- Rolling Mean (7 Days)
- Rolling Standard Deviation (7 Days)

These features capture historical sales trends.

---

### Business Features

Business-specific metrics include:

- Estimated Profit
- Invoice Month

Estimated profit is calculated using a 30% profit margin assumption.

# 7. Machine Learning Integration

The processed data supports multiple AI modules.

## Customer Segmentation

Uses RFM features to group customers based on purchasing behaviour.

---

## Demand Forecasting

Uses historical sales data and time-series features to predict future product demand.

---

## Churn Prediction

Uses customer behaviour metrics to estimate the probability of customer churn.

---

## Inventory Optimization

Uses forecasted demand to recommend:

- Safety Stock
- Reorder Point
- Recommended Order Quantity

This helps reduce stock-outs and overstock situations.
